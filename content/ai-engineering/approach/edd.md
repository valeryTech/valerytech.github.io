**Eval-Driven Development (EDD)** is the architectural answer to the non-deterministic nature of AI.

A simplified traditional testing assertion is: `result == expected`.

An illustrative EDD assertion is: `similarity(result, expected) > 0.8`. The metric and threshold must be justified for the task.

Establishing EDD early gives teams a basis for evaluating prompt changes rather than relying on impressions. Relying on impressions can create regression loops where fixing one prompt breaks several other behaviors.

The following blueprint describes an EDD pipeline.

### **I. The Core Concept: The "Pyramid of Evals"**


Just like the "Test Pyramid" (Unit > Integration > E2E), AI has its own hierarchy of verification. This order balances cost and speed.

|---|---|---|---|---|
|**L1**|**Deterministic**|Code-based checks. Binary pass/fail.|Does the JSON have the field `user_id`? Is the response < 500 tokens?|Low / Free|
|**L2**|**Model-Graded**|Using a "Judge" LLM to score a "Student" LLM.|"On a scale of 1-5, how polite is this response?" or "Does the answer contain PII?"|Medium / \[
|
|**L3**|**Human-in-the-Loop**|Experts reviewing logs. Used to _calibrate_ L2.|A lawyer verifying if the legal summary is actually accurate.|High / $

### **II. The Metrics: What is being measured?**


For many RAG and agentic systems, three useful measurement dimensions form the **RAG Triad** (popularized by frameworks like **Ragas**):

1. **Context Precision (The Retrieval Metric):**
	- _Question:_ Did the search engine find the right documents?
	- _Failure Mode:_ The LLM gave a bad answer because it was fed garbage data ("Garbage In, Garbage Out").
2. **Faithfulness (The Hallucination Metric):**
	- _Question:_ Is the answer derived _solely_ from the retrieved context?
	- _Failure Mode:_ The LLM ignored the documents and made up facts based on its training data.
3. **Answer Relevance (The User Metric):**
	- _Question:_ Did the answer actually address the user's prompt?
	- _Failure Mode:_ The answer is true, but it's a non-sequitur (e.g., User: "Price?" AI: "The product is blue.").

### **III. The Mechanism: "LLM-as-a-Judge"**


This is the engine of modern EDD. Manual review of 1,000 logs for each prompt update is costly; automated judging can support repeated evaluation.

How it works:

A highly capable model is deployed (e.g., GPT-4o or Claude 3.5 Sonnet) to act as the "Judge." It evaluates the traces generated by the production model (e.g., Llama-3-8B).

**The Architectural Pattern:**

1. **Dataset:** A set of 50 "Golden Questions" + "Ideal Answers" (Ground Truth).
2. **Run:** Pipeline processes the 50 questions.
3. **Eval:** The "Judge" model compares the _Pipeline Output_ vs. _Ideal Answer_.
4. **Score:** Returns a structured JSON: `{ "score": 0.85, "reasoning": "Missed the nuance about the date." }`.

### **IV. Implementing the EDD Pipeline (CI/CD for AI)**


Integrate evaluation into the DevOps lifecycle.

#### **1. The Tooling**


Don't build this from scratch. Use established open-source tools:

- **Promptfoo:** Excellent for developer-centric, local CLI testing. Great for diffing prompt changes.
- **DeepEval / Ragas:** Python libraries specifically for calculating the RAG metrics mentioned above.
- **LangSmith / Arize:** Cloud platforms for managing datasets and running these evals on historical traces.

#### **2. The Workflow**


**Scenario:** A developer wants to change the System Prompt to be "more concise."

- **Step 1 (Local):** Developer runs `promptfoo eval` on their laptop against a subset of 10 test cases.
	- _Result:_ Pass.
- **Step 2 (PR):** Developer opens a Pull Request.
- **Step 3 (CI):** GitHub Actions triggers the full regression suite (100 test cases).
	- _Check:_ `avg_faithfulness` dropped from 0.92 \(\rightarrow\) 0.85.
	- _Action:_ **Build Failed.**
- **Step 4 (Review):** Developer inspects the failures, realizes "concise" made the model skip important safety warnings, and fixes the prompt.

### **V. Summary Checklist for the Principal Architect**


Three questions assess evaluation readiness:

1. **"Is there a Golden Dataset?"** (If no, start curating 20 high-quality examples today).
2. **"Are inputs and outputs logged?"** (Raw data supports future datasets).
3. **"Is there a regression test?"** (Can a prompt change be checked for regressions?).
